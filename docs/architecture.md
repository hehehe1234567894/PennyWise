# PennyWise 架构决策记录

> 目标：不逐项手动记账。截图/复制交易信息 → 多模态 LLM 解析 → 本地数据库 → 数据驱动的消费规划与替代方案。
> 约束：Windows + iPhone；不购买服务器；校园网（AP 隔离、无公网 IP、可能限流）；可接受云端 LLM；开发尽量由 AI 完成。

## 总体架构

```
iPhone（采集 + 查看）                 Windows PC（中枢，免费"服务器"）
┌─────────────────────┐     ┌─────────────────────────────────┐
│ 粘贴文本 / 截图分享   │────▶│ Node + Express 服务 (0.0.0.0)     │
│ PWA（离线队列）      │隧道  │   ├─ SQLite 单文件账本 (data/)    │
│ 待确认卡片 / 流水 / 统计│◀────│   ├─ LLM 解析（OpenAI 兼容接口） │
└─────────────────────┘     │   └─ 后续: 视觉解析 / CSV 对账 / Agent│
                            └─────────────────────────────────┘
```

- 手机是**瘦客户端**：PWA（Safari 添加到主屏幕），无 App Store、无开发者账号。
- 数据源优先级：**微信/支付宝账单 CSV（每月，零错误）> 交易通知文本 > 截图 OCR**。CSV 是主数据源，实时采集是补丁，二者用对账流程调和。
- 解析结果**永远先进入"待确认"队列**，一键确认后入账——这是准确性的根本保障，而不是把 LLM 输出直接入库。

## 传输层：校园网下的三层容灾

1. **Tailscale（主通道）**：手机与电脑各自登录同一账号，流量走 WireGuard 端到端加密。宿舍 AP 隔离导致 P2P 打洞失败时自动降级到官方 DERP 中继（TCP 443，校园网几乎不可能封）。访问地址固定（`100.x.x.x` 或机器名域名），出门/蜂窝网络同样可用，**代码无需任何网络环境判断**。
   - 推荐在 Windows 上执行 `tailscale serve --bg 8720`，获得 `https://<机器名>.<tailnet>.ts.net` 的自动证书 HTTPS。**必须用 HTTPS**：Service Worker 和剪贴板 API 只在安全上下文可用，纯 HTTP 会静默失去离线缓存能力。
2. **端点自动检测（在家直连内网）**：服务端 `/api/reachability` 自报端口、LAN IP、Tailscale IP（按网卡名/100.x 前缀识别）与可选 `TAILSCALE_NAME`；手机端并发探测所有候选（2.5s 超时），**优先局域网直连，失败自动回退 Tailscale**，60s 周期重测 + 请求失败即时重探测 + 设置页手动重测。顶栏显示当前通道，设置页一键"打开"其他地址（AUTH_TOKEN 随 URL 片段传递，免重输）。浏览器混合内容限制：HTTPS 页面不能请求 HTTP 内网地址，跨协议切换靠用户点击链接完成（顶栏跳转允许）。CORS 全开 + 令牌鉴权保证跨地址调用可行且安全。
3. **离线队列（PWA 内置）**：网络抖动时交易先存手机 IndexedDB，恢复后自动补传；`client_id` 幂等去重保证重试不重复入库。
4. **兜底**：手机反向热点（PC 连手机热点）；同屋场景直接用电脑上的微信/支付宝客户端复制通知文本，粘进 PC 网页版——天然离线。

### 蓝牙评估（结论：v1 不做，接口预留）

- BLE 有效距离约 10 米，只覆盖"手机与电脑同屋且所有网络不可用"这一个场景，不是校园级通道。
- iOS Safari 不支持 Web Bluetooth → PWA 用不了蓝牙，必须原生 App；无 Mac 时只能 GitHub Actions macOS 云构建 + AltStore 自签，免费账号每 7 天重签一次；Windows 端 GATT server（BLE 外设）支持参差，台式机常需另购蓝牙适配器。
- 同屋场景的零成本替代：电脑微信/支付宝客户端复制通知 → PC 网页版直接粘贴。
- 传输层在代码中以 API 端点形式解耦（服务只认 HTTP），未来若做原生 App（顺带解锁蓝牙、截图分享、通知扩展），无需改动服务端。

## 数据模型（v1）

- `transactions`：时间/金额/方向（expense·income·refund·transfer）/商户/分类/账户（wechat·alipay·bank·cash·other）/原文/来源（text·manual，后续 image·csv）/状态（pending·confirmed）/置信度/备注/是否人工改过。
- `rules`：商户 → 分类的记忆表。每次确认入账时学习；同一商户再次解析时自动套用历史分类并提高置信度——这是"越用越准"的正反馈机制。
- `categories`：默认分类可扩展。数据库文件为 `data/pennywise.db`，备份即复制该文件。

## LLM 分层

| 任务 | 默认模型 | 说明 |
|---|---|---|
| 文本解析 | DeepSeek `deepseek-chat` | 严格 JSON 输出，含微信/支付宝/银行通知 few-shot |
| 视觉解析（阶段 2） | 智谱 `glm-4v-flash` | 截图 OCR + 结构化提取 |
| 规划/月报/比价（阶段 4-5） | 任意文本模型 + 联网搜索工具 | 比价必须搜索接地，禁止凭记忆报价格 |
| 隐私兜底 | 本地 Ollama（如 Qwen2.5-VL） | 同一套 OpenAI 兼容接口，换 `.env` 即可 |

所有模型调用由 PC 发起（手机不直连 LLM）；发图给云端前先本地脱敏（卡号等）。成本量级：几百笔/月 ≈ 几元。

## 安全

- `AUTH_TOKEN` 共享密钥保护全部 `/api/*` 写操作（个人内网场景足够；Tailscale 隧道本身端到端加密）。
- 不做端口映射、不暴露公网；Tailscale Serve 只对 tailnet 内设备可见。
- 财务数据只落本地 SQLite，是否上云由 LLM 配置决定（本地模型可完全离线）。

## 路线图

- **v1（当前）**：文本采集 → LLM 解析 → 确认入账 → 流水/统计；PWA 离线队列；Tailscale 接入。
- **v2**：截图视觉解析（快捷指令分享 → PC → 视觉模型 → 确认卡片）。
- **v3**：微信/支付宝账单 CSV 导入 + 自动对账（时间/金额模糊匹配，异常进人工队列）。
- **v4**：月报 agent、预算与超额提醒（PC 定时任务，agent 只读工具）。
- **v5**：替代消费方案 agent（搜索接地比价），可选蓝牙通道（需原生 App）。
